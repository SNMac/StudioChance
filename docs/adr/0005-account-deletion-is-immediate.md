# 계정 삭제는 즉시 확정되며 복구 기간을 두지 않는다

계정 삭제는 Firebase Auth 계정을 그 자리에서 지운다. 같은 Google·Apple 계정으로 다시 로그인하면 Firebase가 새 uid를 발급하므로 예전 사용자 문서와 이어질 방법이 없다. 그래서 "7일 안에 재로그인하면 복구"라는 개념을 버리고, 계정 삭제를 되돌릴 수 없는 행위로 정한다. 여러 소셜 로그인은 Firebase가 한 계정으로 통합하도록 두며(같은 이메일), 계정 삭제는 연동된 제공자 전체에 적용된다.

계정을 삭제하면 다른 멤버가 없는 관리자 점포는 Soft Delete하고, 나머지 점포에서는 모두 나가며, 승인 대기 중인 신청은 모두 취소한다. Soft Delete한 점포는 복구 여유 기간(7일) 없이 바로 만료시킨다. 관리자 계정이 사라져 되살려도 쓸 사람이 없기 때문이다. 사용자 문서는 지우지 않고 닉네임과 `deletedAt`만 남도록 덮어쓴다(닉네임이 없으면 소셜 계정 이름을 닉네임 최대 길이까지만). 남은 예약의 작성자와 멤버 변동 알림 문구에 이름이 필요하기 때문이다. 점포 멤버 값에는 이름을 넣을 수 없고(ADR-0004), 예약마다 이름을 스냅샷으로 두면 알림 함수가 읽을 수 없다.

사용자 문서는 작성한 예약이 남아 있는 동안만 둔다. 예약이 모두 사라지면(삭제, 다른 점포로 이동, 점포 삭제) 이름을 남길 이유가 없으므로 Functions의 `purgeDeletedUsers`가 매주 지운다. 탈퇴한 사람의 이름을 필요 이상으로 보관하지 않기 위해서다. 삭제한 지 7일이 지난 계정만 지우므로, 작성한 예약이 없던 사용자라도 계정 삭제가 일으킨 점포 나가기 알림은 이름을 읽을 수 있다. 계정 삭제 화면을 만들 때는 "작성한 예약이 남아 있는 동안 닉네임이 남는다"고 안내한다.

Apple 토큰 revoke는 Firestore 쓰기보다 먼저 실행한다. 사용자가 취소했거나 네트워크 오류이면 아무것도 바꾸지 않고 멈추고, 그 밖의 실패는 Crashlytics에 기록한 뒤 삭제를 계속한다. Firebase 콘솔의 Apple 설정 오류 하나로 모든 Apple 사용자가 계정을 삭제하지 못하게 되는 것을 막기 위해서다. 사용자는 Apple ID 설정에서 직접 연결을 끊을 수 있다.

#25에서 "스태프·뷰어가 계정을 삭제해도 멤버십을 남긴다"고 정한 것은 복구를 전제로 했으므로 이 결정으로 뒤집힌다.

## Considered Options

- **복구 기간 7일**: 계정 삭제 때 Auth를 지우지 않고 비활성으로 표시하고, 7일 뒤 스케줄 함수가 Admin SDK로 Auth와 데이터를 지운다. 기간 안에 다시 로그인하면 같은 uid로 들어오므로 복구할 수 있다. 다만 스케줄 함수, 복구 시 `storeById` 재구성, 다른 기기에 남은 세션이 의도치 않게 복구하는 문제(`revokeRefreshTokens`를 쓰려면 계정 삭제를 Callable로 옮겨야 함), 유예 기간 중 멤버 표시 방식까지 모두 새로 필요하다. 출시 전에 실수로 삭제한 사용자를 구제하려고 감수할 비용이 아니라고 봤다. 필요해지면 이 방식에서 출발한다. Apple revoke는 그때도 계정 삭제 시점에 바로 하면 된다. Auth 레코드가 남아 있으면 revoke 후에도 같은 uid로 다시 로그인된다.
- **새 uid로 로그인할 때 이메일·제공자 ID로 예전 문서를 찾아 옮기기**: 문서 이전, 점포 멤버 키 교체, 예약 `writerId` 갱신이 얽혀 가장 복잡하다.
- **사용자 문서를 완전히 지우고 예약에 작성자 이름 스냅샷 저장**: 예약 스키마와 모든 쓰기 경로가 바뀌고, 닉네임 변경 반영을 위해 이중 경로가 필요하며, 알림 문구 문제는 해결하지 못한다.
