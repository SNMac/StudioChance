# 점포 삭제는 7일 동안 관리자가 복구할 수 있다

점포 삭제는 점포를 바로 지우지 않고 삭제 예정 점포로 만든다. 7일 동안 멤버의 점포 목록에 남은 기간과 함께 남고, 그 안에 관리자가 앱에서 점포 복구를 할 수 있다. 계정 삭제는 복구 기간 없이 즉시 확정하는데(ADR-0005) 점포 삭제만 되돌릴 수 있게 한 이유는 잃는 것이 다르기 때문이다. 점포를 잘못 지우면 다른 멤버들까지 앞으로 잡힌 손님 예약 전체를 잃는다. 반면 복구는 쉽다. 관리자 uid가 그대로 남으므로 계정 복구처럼 Auth와 세션을 다룰 필요가 없다.

삭제 예정 점포는 읽기 전용이다. 예약과 점포 정보는 그대로 보이지만 Rules가 예약 쓰기와 점포 문서 수정을 막고, 점포 복구·영구 삭제·점포 나가기만 남긴다. 멤버의 사용자 문서에 있는 점포 항목(역할·점포 색상·점포 메모)은 지우지 않는다. 그래야 멤버에게 삭제 예정을 보여줄 수 있고, 복구할 때 멤버마다 고른 값이 그대로 돌아온다. 승인 대기 중인 신청은 점포 삭제 때 정리하고 복구해도 되살리지 않는다. 신청자를 최대 7일 동안 묶어 두지 않기 위해서다.

관리자는 기다리지 않고 영구 삭제를 할 수 있다. 계정을 삭제하려는 관리자를 7일 기다리게 할 수는 없기 때문이다. 영구 삭제는 점포 문서를 바로 지우고, 계정 삭제가 점포를 지우는 경로도 같은 방식을 쓴다. 복구는 관리자만 할 수 있으므로 관리자가 떠난 점포를 남겨 둘 이유가 없다.

## Considered Options

- **운영자가 콘솔이나 Admin SDK로 복구**: 사용자가 문의해야 하고, 7일 안에 운영자가 응답하지 못하면 데이터가 사라진다. 앱 문구는 "되돌릴 수 없다"인데 실제로는 복구할 수 있어 동작과 설명이 어긋난다. 점포 삭제 때 멤버의 점포 항목을 지우므로 점포 색상·점포 메모도 되살릴 수 없었다.
- **즉시 삭제 (계정 삭제와 같은 방식)**: 가장 단순하지만 실수 한 번에 다른 멤버들의 예약까지 되돌릴 수 없게 잃는다.

## Consequences

- 남겨 둔 멤버의 점포 항목은 점포 문서가 실제로 지워질 때 `cascadeStoreDelete`가 함께 지워야 한다. 그러지 않으면 멤버 앱에 사라진 점포가 남는다.
- 남은 기간을 사용자에게 보여주므로 만료 시각은 서버 시각 기준이어야 한다. 만료 시각이 지나면 TTL이 지우기 전이라도 복구할 수 없고, 앱 목록에서도 숨긴다.
- 기간이 끝나 저절로 지워질 때는 알림을 보내지 않는다. 점포 삭제 때 이미 "7일 뒤 삭제"를 알렸기 때문이다. 영구 삭제와 점포 복구는 멤버에게 알린다.
