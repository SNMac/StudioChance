# 공휴일 달력은 Cloud Functions가 동기화해 Firestore에 둔다

공휴일 판정에 공공데이터포털 특일 정보 API(`getRestDeInfo`)를 쓰되, 앱이 직접 부르지 않는다. 스케줄 함수가 매일 04:00 KST에 받아 `holidays/{year}`에 저장하고, 앱은 Firestore만 읽는다. serviceKey를 앱 바이너리에 넣으면 추출될 수 있고, 키당 하루 호출 한도를 모든 사용자 기기가 나눠 쓰게 되어 키 하나가 남용되면 전체 사용자의 공휴일 판정이 멈추기 때문이다. Firestore 오프라인 캐시도 덤으로 얻는다.

## Considered Options

- **앱이 API를 직접 호출하고 기기에 캐시**: 구현이 가장 적지만 위의 키 노출·공유 한도 문제가 남는다.
- **Callable 프록시**: 키는 숨기지만 예약 모달을 열 때마다 cold start와 호출 비용이 든다. 온보딩 1회성인 `lookupInviteCode`(D11)와 달리 공휴일은 상시 필요하다.
- **앱에 정적 테이블 내장**: 임시공휴일 반영에 앱 재배포가 필요하다.

## Consequences

- 쓰기 비용은 걱정할 수준이 아니다. 내용이 바뀐 연도만 쓰므로 실제 쓰기는 1년에 몇 번이다.
- 스케줄은 첫 실행이 다음 날 새벽이라, 배포 직후 dev·prod에서 한 번씩 수동 실행해야 데이터가 생긴다.
- 연도는 서버 시계(UTC)가 아니라 KST 기준으로 계산해야 1월 1일에 연도가 어긋나지 않는다.
