# 이슈 트래커: GitHub

이 저장소의 이슈와 스펙은 GitHub 이슈로 관리한다. 모든 작업에 `gh` CLI를 사용한다.

## 이 저장소의 규칙 (CLAUDE.md `## Git 컨벤션`이 원본)

- 이슈는 반드시 GitHub Issues에 만든다. Linear는 GitHub과 자동 연동되므로 Linear에 직접 만들지 않는다.
- 제목: `<Type>/<한국어 설명>`. Type은 `Feature` / `Bug` / `Refactor` 중 하나이고, 이슈번호는 넣지 않는다.
- 본문: `.github/ISSUE_TEMPLATE/issue_template.md`의 섹션 구성을 그대로 따른다.
  `## 📄 이슈 내용`(인용구 한 문단) / `## 📝 상세 내용`(불릿) / `## ✅ 체크리스트`(`- [ ]`), 섹션 사이에 `<br>`
- 본문에 Claude Code 생성 표기를 넣지 않는다.
- triage 스킬의 AI 생성 고지 문구(`> *This was generated by AI during triage.*`)는 triage가 남기는 코멘트에만 붙인다.

## 명령어

- **이슈 생성**: `gh issue create --title "..." --body "..."`. 여러 줄 본문은 heredoc을 쓴다.
- **이슈 조회**: `gh issue view <number> --comments`. 코멘트는 `jq`로 거르고 라벨도 함께 가져온다.
- **이슈 목록**: `gh issue list --state open --json number,title,body,labels,comments --jq '[.[] | {number, title, body, labels: [.labels[].name], comments: [.comments[].body]}]'`에 필요한 `--label`, `--state` 필터를 붙인다.
- **코멘트 작성**: `gh issue comment <number> --body "..."`
- **라벨 추가 / 제거**: `gh issue edit <number> --add-label "..."` / `--remove-label "..."`
- **닫기**: `gh issue close <number> --comment "..."`

저장소는 `git remote -v`로 판단한다. clone 안에서 실행하면 `gh`가 자동으로 알아낸다.

## PR을 triage 대상으로 다룰지 여부

**PRs as a request surface: no.** _(외부 PR을 기능 요청으로 취급하는 저장소라면 `yes`로 바꾼다. `/triage`가 이 플래그를 읽는다.)_

`yes`이면 PR도 이슈와 같은 라벨·상태를 거치며, 대응하는 `gh pr` 명령을 쓴다.

- **PR 조회**: `gh pr view <number> --comments`, diff는 `gh pr diff <number>`.
- **triage할 외부 PR 목록**: `gh pr list --state open --json number,title,body,labels,author,authorAssociation,comments`를 실행한 뒤 `authorAssociation`이 `CONTRIBUTOR`, `FIRST_TIME_CONTRIBUTOR`, `NONE`인 것만 남긴다(`OWNER`/`MEMBER`/`COLLABORATOR`는 제외).
- **코멘트 / 라벨 / 닫기**: `gh pr comment`, `gh pr edit --add-label`/`--remove-label`, `gh pr close`.

GitHub은 이슈와 PR이 번호 체계를 공유하므로 `#42`만으로는 어느 쪽인지 알 수 없다. `gh pr view 42`로 확인하고, 실패하면 `gh issue view 42`로 넘어간다.

## 스킬이 이슈 트래커에 게시하라고 할 때

GitHub 이슈를 생성한다.

## 스킬이 관련 티켓을 가져오라고 할 때

`gh issue view <number> --comments`를 실행한다.

## Wayfinding 작업

`/wayfinder`가 사용한다. **맵**은 이슈 하나이고, 그 **하위** 이슈들이 티켓이다.

- **맵**: `wayfinder:map` 라벨이 붙은 이슈 하나. 본문에 Notes / Decisions-so-far / Fog 섹션을 둔다. `gh issue create --label wayfinder:map`.
- **하위 티켓**: 맵에 GitHub sub-issue로 연결된 이슈(sub-issues 엔드포인트에 `gh api` 호출). sub-issue를 쓸 수 없으면 맵 본문의 task list에 하위 티켓을 추가하고, 하위 티켓 본문 맨 위에 `Part of #<map>`을 적는다. 라벨: `wayfinder:<type>` (`research`/`prototype`/`grilling`/`task`). 티켓을 맡으면 진행하는 개발자에게 할당한다.
- **블로킹**: GitHub의 **기본 이슈 의존성(issue dependencies)** 을 쓴다. UI에 보이는 정식 표현이다. `gh api --method POST repos/<owner>/<repo>/issues/<child>/dependencies/blocked_by -F issue_id=<blocker-db-id>`로 의존 관계를 추가한다. `<blocker-db-id>`는 블로커 이슈의 숫자 **database id**다(`gh api repos/<owner>/<repo>/issues/<n> --jq .id`. `#number`나 `node_id`가 _아니다_). GitHub은 `issue_dependencies_summary.blocked_by`에 열린 블로커 수만 보고하며, 이것이 실제 진행 가능 여부를 가른다. 의존성 기능을 쓸 수 없으면 하위 티켓 본문 맨 위에 `Blocked by: #<n>, #<n>` 줄을 적는다. 블로커가 모두 닫히면 티켓이 풀린다.
- **진행 가능 티켓 조회**: 맵의 열린 하위 티켓을 나열한다(`gh issue list --state open`, 맵의 sub-issue / task list 범위). 열린 블로커가 있거나(`issue_dependencies_summary.blocked_by > 0`, 또는 `Blocked by` 줄에 열린 이슈가 있음) 담당자가 지정된 티켓은 뺀다. 남은 것 중 맵 순서상 첫 번째를 고른다.
- **맡기**: `gh issue edit <n> --add-assignee @me`. 세션의 첫 쓰기 작업이다.
- **해결**: `gh issue comment <n> --body "<answer>"` → `gh issue close <n>` → 맵의 Decisions-so-far에 맥락 포인터(요지 + 링크)를 추가한다.
